# MAT-1781 — mistakes

Newest first.

## A key-injector thread outlived its test and typed into the next one
- **What:** `tests/e2e_drilldown.py` starts a thread that sends one key per picker round. When a case used fewer rounds than expected the thread stayed parked waiting for a picker that never came, then grabbed the *next* case's picker and sent it a stale `Return` — so the Escape check reported a captured region instead of a cancellation, on two runs out of three. Separately, sending a key once after a fixed sleep is a coin flip: it is dropped if it lands before wl-kbptr's layer surface has taken its keyboard grab.
- **Fix:** A `threading.Event` set and joined in a `finally` around each case, and both e2e scripts now re-send the key until the picker process exits instead of sleeping and hoping.
- **Lesson:** A background driver inside a test needs an explicit lifetime, or it leaks into the next test and produces failures that look like product bugs. Timing-based input needs a completion signal, never a sleep.

## Three fixtures that could not exercise what they claimed
- **What:** In `tests/test_hierarchy.py`: the round-cap fixture used near-identical boxes, which contain each other, so they formed a nested chain rather than the siblings a cap acts on; the narrowing negative control compared a round against itself, because that fixture had exactly one top-level region; and the shared-prefix control shuffled paths but kept path *lengths*, and length correlates with depth and so with size, so the control came out weakly monotone too and monotonicity alone proved nothing.
- **Fix:** Rebuilt each fixture, and switched the prefix metric from "is it monotone" to "is the effect an order of magnitude larger than the shuffled control's".
- **Lesson:** Write the failing case and watch it fail. "The assertion is green" and "the assertion is testing something" are different claims, and only the second one is worth anything.

## The eval printed STRUCTURAL PASS on zero scored images
- **What:** `tests/harness.py` computed its verdict from summed counters. When every detection run crashed, the totals were all 0 and it printed `images scored 0/1` followed by `verdict: STRUCTURAL PASS` — a completely broken detector reading as a clean bill of health.
- **Fix:** The verdict now requires every image to have scored and the result set to be non-empty, and says outright that the invariants are vacuous otherwise.
- **Lesson:** An "all counters zero" pass condition is indistinguishable from "nothing ran". Make a check require positive evidence, not the absence of failures.

## wl-kbptr needs `n < num_symbols` for a one-character label
- **What:** Each hierarchy round was sized at `len(symbols)` = 26, expecting one keystroke per round. `label.c` computes label width with `while (n > 0) { len++; n /= num_symbols; }`, so exactly 26 labels over 26 symbols divides to 1 and takes a second pass — every round silently cost TWO keystrokes. The structural checks could not see it: they only saw rounds of 26, which looked right. It showed up as the keystroke mean sitting at 5.5 while the tree got three times shallower.
- **Fix:** `one_keystroke_max()` returns `len(symbols) - 1`, and the round budget now counts the current region, which also occupies a label slot. `test_hierarchy.py` guards the boundary in both directions.
- **Lesson:** When reproducing another program's arithmetic, run its formula on the boundary case. And when a metric refuses to move after a change that should have moved it, that disagreement *is* the bug — not noise.
